- **2026-08-12 — Phase 3 agent runtime + Director + Script agent complete.** Built the Anthropic tool-use wrapper from scratch (`backend/src/ai/agents/tool-agent-runtime.ts`) — the largest net-new piece so far, since no raw tool-use pattern existed anywhere (all existing chains use LangChain + plain-JSON-in-prompt parsing). It forces structured output by requiring the model to call a dedicated output tool, validates the result with zod, and does exactly one JSON-repair retry (sends validation errors back as a tool_result, or nudges the model back onto the tool if it answered in prose) before failing loudly with `AgentOutputValidationError`. Bounds enforced: `maxToolCalls` (worker-tool calls only, output-tool call is free) and `tokenBudget`, both throwing `AgentBoundsExceededError` when exceeded. Built the Script agent (`script-agent.ts`, zero worker tools — tool-use here is pure structured-output enforcement) and the Director (`director.service.ts` + `video-director.worker.ts` on a new `video-director` BullMQ queue) — Director persists a placeholder `VideoPlan` row in `draft` status before calling the LLM, then updates to `in_review` with the final plan once the Script agent returns; never auto-enqueues a render (technician approval gates render, per the pipeline's core design principle). Tests: 41/41 passing across 5 new spec files, including a forced-malformed-output-then-repair test, a worker-tool-execution test, bounds-exceeded tests for both tool calls and token budget, and — the phase's required end-to-end check — `director-render-compat.spec.ts`, proving a Director-drafted plan feeds straight into Phase 2's `buildShotstackEditFromPlan` with zero changes to either side. SDK note: `@anthropic-ai/sdk` is pinned at `0.20.0` in this repo, which predates tool-use graduating out of beta — the runtime calls `client.beta.tools.messages.create(...)` (same wire contract; upgrading the SDK later is a drop-in). `tsc --noEmit`: initially found real type errors in the new runtime (see next entry) — fixed before commit. - **2026-08-12 — Phase 5 QA/critic loop complete.** Built the Critic agent (`critic-agent.ts`, zero worker tools — pure judgment, same structured-output pattern as Script agent) scoring drafts 0-1 against a rubric (on-brand, matches objective, hook strength, pacing, compliance) and naming weak scene indices. Pass/fail is decided in code against `CRITIC_PASS_THRESHOLD`, never trusted from the model directly — same "agent reasons, code decides" split used everywhere else in this pipeline. `DirectorService` gained `runCriticLoop` (private, shared by both `draftSlideshowPlan` and `draftReelsPlan`): scores the draft, and if below threshold asks the Script agent to rewrite ONLY the flagged scenes (`ScriptAgentParams.revision`, new optional param — previous scenes + critic notes + which indices to fix), merges the result back by index (`mergeSceneCopy`), and re-critiques — bounded to `MAX_CRITIC_REVISIONS` (2). Runs once per draft, entirely on scene text, before reels' asset/voiceover resolution — so a revision cycle never re-triggers ElevenLabs or stock-image search. `plan.critic` and the denormalized `VideoPlan.criticStatus/criticScore/criticRevisions` columns both come from the same result, so they can't drift apart. Tests: 68/68 passing across 15 suites (up from 62), including the phase's two required self-tests in `director.service.spec.ts`'s new "critic revision loop" block — a deliberately weak seeded draft (score 0.4) triggers exactly one targeted revision and returns passed with a higher score (0.85), and a permanently-failing critic mock proves the loop stops at exactly `MAX_CRITIC_REVISIONS` (3 script calls, 3 critiques — 1 initial + 2 revisions — never more). `tsc --noEmit` clean. Note: a plan that never passes still reaches the technician for review with the critic's notes visible (not blocked) — only render/publish is meant to gate on `critic.passed`, which isn't enforced anywhere in code yet; flagged for Phase 8's approve/publish UI. Committed locally on `dev-prashant` (not pushed). Next: Phase 6 — Compliance agent + code-enforced hard gate. - **2026-08-12 — Phase 6 Compliance agent + code hard gate complete.** Two layers as specified.
